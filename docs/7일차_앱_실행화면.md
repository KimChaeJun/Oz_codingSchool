# 7일차 앱 실행화면

Day 6까지 구현된 FastAPI 백엔드에 `static/` 프론트엔드 템플릿을 연결한 뒤(과제 1), 실제로
`fastapi run app/main.py`로 서버를 띄우고 `http://localhost:8000`에서 각 화면을 직접 조작하며 동작을 확인함.

테스트에 사용한 계정: `live-http-check@example.com`(STAFF, 환자/진료기록/AI예측 테스트용),
관리자 화면(16~18번)만 별도로 임시 생성한 테스트 계정을 ADMIN으로 승격해 확인 후 삭제함.

## 1. 회원가입

- **HTTP Method / Endpoint**: `POST /api/v1/auth/signup`
- **프론트엔드에서 수행한 동작**: `/signup` 페이지에서 이메일, 이름, 부서(select: `DEV`/`MEDICAL`/`RESEARCH`), 성별(select: `M`/`F`), 전화번호, 비밀번호를 입력하고 "가입하기" 클릭
- **정상 동작 결과**: "회원가입이 완료되었습니다. 로그인해주세요." 알림 표시 후 로그인 페이지로 이동
- **관련 화면 캡처**:

  ![회원가입 성공](images/day7/01_회원가입_성공.png)

## 2. 로그인 / 4. 환자 목록

- **HTTP Method / Endpoint**: `POST /api/v1/auth/login`, `GET /api/v1/patients`

- **정상 동작 결과**: 별도 알림 없이 네비게이션이 로그인 상태(사용자명·부서 표시, 로그아웃 버튼)로 바뀌고, 환자 목록이 테이블로 렌더링됨

## 8. 환자 수정/삭제

- **HTTP Method / Endpoint**: `PATCH /api/v1/patients/{patient_id}`, `DELETE /api/v1/patients/{patient_id}`
- **프론트엔드에서 수행한 동작**:
  - 수정: 환자 상세 화면에서 "정보 수정" → 이름 변경 후 "수정 완료"
  - 삭제: "삭제" → 확인 모달에서 "확인했습니다" 클릭
- **정상 동작 결과**:
  - 수정: "환자 정보가 수정되었습니다" 알림과 함께 변경된 이름이 즉시 반영됨
  - 삭제: 확인 모달 노출 → "환자 정보와 관련 데이터가 모두 삭제되었습니다" 알림 후 목록에서 제거됨

## 9. 진료기록 등록

- **HTTP Method / Endpoint**: `POST /api/v1/medical-records` (multipart/form-data: `patient_id`, `chart_number`, `symptoms`, `xray_image`)
- **프론트엔드에서 수행한 동작**: 환자 상세 화면에서 "진료 기록 등록" → 차트번호/증상 입력, X-Ray 이미지 업로드 → 제출
- **정상 동작 결과**: 등록 성공 후 환자 상세의 진료기록 목록에 새 레코드(차트번호 `DOC-DEMO-001`)가 표시됨

  ![진료기록 등록](images/day7/09_진료기록_등록.png)

## 11. AI 신규 예측 실행

- **HTTP Method / Endpoint**: `POST /api/v1/medical-records/{record_id}/predictions`
- **프론트엔드에서 수행한 동작**: 진료기록 상세 화면에서 "AI 예측 결과보기" 클릭 (해당 진료기록은 이전에 예측을 수행한 적 없는 신규 기록)
