## 잘된 점

1. `CurrentStaff` 의존성을 사용해 프로젝트의 승인된 사내 사용자 권한 정책을 재사용했습니다.
2. 예측 결과 조회 API가 요구사항대로 목록을 반환하며 응답 필드도 설계 문서와 일치합니다.
3. 작업별 결과 채널을 사용해 서로 다른 예측 요청의 메시지가 섞이지 않도록 했습니다.
4. FastAPI 이미지에는 웹 의존성만, AI Worker 이미지에는 Torch 계열 의존성만 설치해 역할을 분리했습니다.
5. 캐시 적중, Redis 장애, timeout, 잘못된 이미지, 경로 이탈, DB 저장, 성능, 실제 Redis 연동을 포함한 테스트가 준비되어 있습니다.
6. 로컬 Redis를 연결한 전체 검증에서 Windows 심볼릭 링크 권한 문제 한 건을 제외하고 45개가 통과하고 1개가 알려진 동시성 한계로 분류되었습니다.

## 병합 전 수정사항

1. Compose의 MySQL 서비스가 `.env.example`의 `DB_USER`/`DB_PASSWORD` 사용자를 실제로 생성하도록 설정합니다.
2. FastAPI 컨테이너 시작 전에 `alembic upgrade head`를 실행하고 MySQL·Redis healthcheck 완료 후 기동하도록 변경합니다.
3. 예측 결과 대기 timeout을 15초에서 요구사항 상한인 3초로 줄입니다.
4. `(record_id, ai_model)` DB 유일 제약과 `IntegrityError` 복구 처리를 추가해 동시 요청의 중복 결과 저장을 막습니다.
5. 결과 대기 도중 Redis 연결이 끊기는 경우도 503 응답으로 변환합니다.
6. Redis 장애 시 Worker가 과도하게 재접속하지 않도록 짧은 재시도 간격을 추가합니다.
7. 관리자 권한이 없는 Windows에서도 테스트 모음이 정상 완료되도록 심볼릭 링크 테스트를 조건부 skip 처리합니다.
