# 3일차 프로젝트 템플릿 뜯어보기

## 1. 프로젝트 개요

이 프로젝트는 흉부 X-Ray 이미지를 활용한 폐렴 판독 모델을 웹 서비스로 제공하고, 환자와 판독 결과를 관리하는 백오피스를 만들기 위한 FastAPI 프로젝트입니다.

전체적인 요청 처리 흐름은 다음과 같습니다.

```text
클라이언트
    ↓ HTTP 요청
FastAPI Router
    ↓ 요청 데이터 검증
Pydantic Schema
    ↓ 업무 처리
Service
    ↓ 데이터 조회·저장
Repository
    ↓ ORM을 통한 데이터베이스 접근
SQLAlchemy Model
    ↓
데이터베이스
```

## 3. 디렉터리별 역할

### 3-1. `app/core/`

프로젝트 전체에서 공통으로 사용하는 핵심 설정을 관리합니다.

- `config.py`: 환경 변수와 프로젝트 설정 관리
- `db/databases.py`: 데이터베이스 URL, 비동기 엔진, 세션 설정
- `db/models.py`: UUID, 생성일, 수정일, 소프트 삭제 등 공통 모델 기능

#### `app/core/config.py`

이 프로젝트는 `pydantic-settings`의 `BaseSettings`를 사용하여 `.env` 파일의 데이터베이스 정보를 읽습니다.

```python
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    DB_USER: str = "root"
    DB_PASSWORD: str = "password1234"
    DB_HOST: str = "localhost"
    DB_PORT: str = "3306"
    DB_NAME: str = "ai_health"

    model_config = {
        "env_file": ".env",
        "extra": "ignore",
    }


settings = Settings()
```

비밀번호나 데이터베이스 주소를 Python 코드에 직접 작성하면 보안에 취약하고 환경이 바뀔 때 수정하기 어렵습니다. 실제 값은 `.env`에 작성하고 Python에서는 `settings.DB_HOST`와 같은 방식으로 사용합니다.

### 3-2. `app/models/`

데이터베이스 테이블을 Python 클래스로 표현하는 SQLAlchemy ORM 모델을 작성합니다.

최종 프로젝트에서는 다음과 같은 모델이 필요할 수 있습니다.

- 환자 정보 모델
- X-Ray 이미지 모델
- AI 판독 결과 모델
- 관리자 또는 사용자 모델

모델의 클래스는 테이블이 되고, 클래스의 속성은 테이블의 컬럼이 됩니다.

### 3-3. `app/repositories/`

데이터베이스에 접근하는 로직을 모아두는 디렉터리입니다.

- 환자 전체 조회
- 특정 환자 조회
- 환자 정보 등록
- 환자 정보 수정 및 삭제
- 판독 결과 조회

API Router가 데이터베이스에 직접 SQL을 작성하면 코드가 복잡해집니다. Repository에 데이터 접근 코드를 모아두면 API와 Service가 데이터베이스의 구체적인 처리 방식을 몰라도 됩니다.

### 3-4. `app/schemas/`

API 요청 데이터와 응답 데이터의 형식을 정의합니다. FastAPI에서는 Pydantic을 사용하여 자료형과 필수값을 검증합니다.

```python
from datetime import date
from pydantic import BaseModel


class PatientCreateRequest(BaseModel):
    name: str
    birth_date: date
    gender: str
```

요청용 Schema와 응답용 Schema를 분리하면 민감한 정보가 응답에 포함되는 것을 막고, API 문서에 요청·응답 형식을 명확하게 표시할 수 있습니다.

### 3-5. `app/services/`

애플리케이션의 핵심 비즈니스 로직을 작성합니다.

폐렴 환자 관리 서비스에서는 다음과 같은 로직이 Service에 들어갈 수 있습니다.

- 동일 환자의 중복 등록 여부 확인
- X-Ray 이미지 업로드 가능 여부 확인
- AI 모델에 이미지 전달
- AI 판독 결과를 정상, 의심, 폐렴 등으로 변환
- 여러 Repository의 결과를 조합하여 대시보드 데이터 생성

API Router는 HTTP 요청과 응답에 집중하고 실제 업무 처리는 Service에 맡기는 것이 좋습니다.

### 3-6. `app/apis/`

클라이언트의 HTTP 요청을 받아 처리하는 API Router를 작성합니다.

- URL 경로와 HTTP Method 정의
- 요청 Schema와 응답 Schema 연결
- Service 호출
- HTTP 상태 코드와 예외 처리

```python
from fastapi import APIRouter

router = APIRouter(prefix="/api/v1/patients", tags=["patients"])


@router.get("/")
async def get_patients():
    return {"message": "환자 목록"}
```

작성한 Router는 `app/main.py`에서 `app.include_router(router)`로 등록해야 실제 API로 사용할 수 있습니다.

## 4. 주요 파일의 역할

### 4-1. `app/main.py`

FastAPI 애플리케이션을 생성하고 Router와 정적 파일 경로를 등록하는 시작점입니다.

현재 프로젝트의 `main.py`는 다음 작업을 수행합니다.

1. `FastAPI()`로 애플리케이션 생성
2. API Router 등록
3. `/static` 경로에 정적 파일 연결
4. `/media` 경로에 업로드 파일 연결
5. `/healthcheck`로 서버 상태 확인
6. `/docs`에서 Swagger UI 제공

```python
from fastapi import FastAPI
from app.apis.practice_apis import router

app = FastAPI()
app.include_router(router)
```

서버 실행 명령은 다음과 같습니다.

```bash
python -m uvicorn app.main:app --reload
```

실행 후 `http://127.0.0.1:8000/docs`에서 API 목록과 요청·응답 형식을 확인할 수 있습니다.

### 4-2. `app/core/config.py`

환경 변수와 프로젝트 실행 설정을 관리합니다.

- `DB_USER`: 데이터베이스 사용자 이름
- `DB_PASSWORD`: 데이터베이스 비밀번호
- `DB_HOST`: 데이터베이스 서버 주소
- `DB_PORT`: 데이터베이스 포트
- `DB_NAME`: 데이터베이스 이름

`.env` 파일은 비밀번호가 포함될 수 있으므로 Git에 올리지 않고 `.env.example`만 공유하는 방식이 안전합니다.

### 4-3. `pyproject.toml`

Python 프로젝트의 기본 정보와 필요한 패키지를 관리합니다.

현재 프로젝트의 주요 의존성은 다음과 같습니다.

- `fastapi[standard]`: FastAPI 웹 프레임워크와 실행 도구
- `sqlalchemy[asyncio]`: 데이터베이스 ORM과 비동기 처리
- `asyncmy`: MySQL 비동기 드라이버
- `alembic`: 데이터베이스 마이그레이션
- `pydantic-settings`: 환경 변수 기반 설정
- `uuid6`: UUID 생성

또한 `requires-python`을 통해 Python 3.13 이상을 사용하도록 설정합니다.

### 4-4. `uv.lock`

프로젝트에 설치되는 패키지와 하위 의존성의 정확한 버전을 기록합니다.

`pyproject.toml`이 필요한 패키지의 종류와 버전 범위를 관리한다면, `uv.lock`은 실제로 설치할 버전을 고정합니다. 팀원이 같은 lock 파일을 사용하면 환경 차이로 인한 오류를 줄일 수 있습니다.

## 5. 데이터베이스 연결 설정

### 5-1. `app/core/db/databases.py`

이 파일은 애플리케이션과 데이터베이스를 연결하는 설정을 담당합니다. 현재 템플릿은 MySQL과 비동기 SQLAlchemy를 사용합니다.

데이터베이스 URL 형식은 다음과 같습니다.

```text
mysql+asyncmy://사용자:비밀번호@호스트:포트/데이터베이스이름
```

주요 구성 요소는 다음과 같습니다.

- `DATABASE_URL`: 데이터베이스 접속 주소
- `create_async_engine`: 비동기 데이터베이스 엔진 생성
- `async_sessionmaker`: 데이터베이스 세션을 생성하는 공장
- `Base`: SQLAlchemy 모델이 상속할 공통 기반 클래스
- `async_get_db`: API에서 사용할 세션을 제공하는 함수

```python
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

DATABASE_URL = "mysql+asyncmy://user:password@localhost:3306/ai_health"

async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,
    autoflush=False,
    expire_on_commit=False,
)
Base = declarative_base()
```

`AsyncSession`을 사용하면 비동기 API에서 데이터베이스 응답을 기다리는 동안 다른 요청을 처리할 수 있습니다.

### 5-2. 데이터베이스 세션 사용

API에서 세션을 사용할 때는 FastAPI의 의존성 주입 기능을 이용할 수 있습니다.

```python
from typing import Annotated
from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.db.databases import async_get_db

DbSession = Annotated[AsyncSession, Depends(async_get_db)]
```

API 함수가 호출되면 세션이 생성되고, 작업이 끝나면 세션이 정리됩니다.

## 6. SQLAlchemy ORM 모델 작성

### 6-1. ORM이란?

ORM(Object-Relational Mapping)은 데이터베이스 테이블을 Python 객체로 다루는 방법입니다. SQL을 직접 작성하는 대신 Python 클래스와 메서드로 데이터를 조회하고 저장할 수 있습니다.

### 6-2. 모델 작성 예시

```python
from sqlalchemy import String
from sqlalchemy.orm import Mapped, mapped_column

from app.core.db.databases import Base


class Patient(Base):
    __tablename__ = "patients"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    diagnosis_status: Mapped[str] = mapped_column(String(30), nullable=False)
```

주요 문법은 다음과 같습니다.

- `Base`: SQLAlchemy 모델의 공통 부모 클래스
- `__tablename__`: 데이터베이스 테이블 이름
- `Mapped[int]`: 컬럼의 Python 자료형
- `mapped_column`: 컬럼 자료형과 제약 조건 설정
- `primary_key=True`: 기본 키 설정
- `nullable=False`: 반드시 값이 있어야 함

최종 프로젝트에서는 ERD를 기준으로 환자, 이미지, 판독 결과 등 필요한 테이블을 각각 모델로 작성합니다.

## 7. Alembic 마이그레이션

Alembic은 SQLAlchemy 모델의 변경 사항을 데이터베이스에 반영하고 변경 이력을 관리하는 도구입니다.

### 7-1. `alembic/env.py`의 역할

현재 프로젝트의 `alembic/env.py`는 다음 작업을 합니다.

1. 프로젝트의 `DATABASE_URL`을 읽습니다.
2. `Base.metadata`를 Alembic에 전달합니다.
3. `app.models`를 불러와 모델을 인식시킵니다.
4. 비동기 엔진을 사용해 마이그레이션을 실행합니다.

모델을 작성했더라도 Alembic이 모델을 알지 못하면 자동으로 변경 사항을 찾을 수 없습니다. 따라서 모델을 import하는 과정이 중요합니다.

### 7-2. 마이그레이션 파일 생성

모델을 새로 만들거나 컬럼을 수정한 뒤 다음 명령어를 실행합니다.

```bash
uv run alembic revision --autogenerate -m "환자 모델 추가"
```

`--autogenerate`는 모델과 데이터베이스의 차이를 비교하여 마이그레이션 초안을 만듭니다. 생성된 파일은 반드시 직접 열어 테이블 생성, 컬럼 추가, 외래 키 설정 등이 올바른지 확인해야 합니다.

### 7-3. 데이터베이스에 적용

```bash
uv run alembic upgrade head
```

`head`는 가장 최신 마이그레이션까지 적용한다는 뜻입니다.

### 7-4. 현재 버전 확인

```bash
uv run alembic current
```

### 7-5. 마지막 마이그레이션 되돌리기

```bash
uv run alembic downgrade -1
```

마이그레이션 파일은 데이터베이스 구조 변경 이력이므로 팀 프로젝트에서는 Git으로 함께 관리해야 합니다.

## 8. API 구현 흐름

환자 등록 API를 예로 들면 다음 순서로 구현합니다.

1. **요구사항 정리**: URL과 HTTP Method를 결정합니다. 예를 들어 `POST /api/v1/patients`입니다.
2. **SQLAlchemy Model 작성**: 데이터베이스에 저장할 환자 테이블의 컬럼을 정의합니다.
3. **Pydantic Schema 작성**: 등록 요청과 응답의 데이터 형식을 정의합니다.
4. **Repository 작성**: 환자 조회, 저장, 수정, 삭제 코드를 작성합니다.
5. **Service 작성**: 중복 환자 확인 등 업무 규칙을 작성합니다.
6. **API Router 작성**: URL, HTTP Method, Schema, Service를 연결합니다.
7. **Router 등록**: `app/main.py`에서 `app.include_router(router)`로 등록합니다.
8. **마이그레이션 실행**: Alembic으로 모델 구조를 데이터베이스에 반영합니다.
9. **Swagger UI 테스트**: `http://127.0.0.1:8000/docs`에서 요청과 응답을 확인합니다.

```text
Client
  ↓ HTTP Request
API Router
  ↓
Request Schema 검증
  ↓
Service 비즈니스 로직
  ↓
Repository 데이터베이스 접근
  ↓
SQLAlchemy Model
  ↓
Database
  ↑
Response Schema
  ↑
Client에게 HTTP Response 반환
```
