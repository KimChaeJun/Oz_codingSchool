# 3일차 - FastAPI 프로젝트 구조 분석

## 프로젝트 개요
이 프로젝트는 FastAPI를 활용한 인공지능 모델 서빙 웹 애플리케이션입니다. 
**Clean Architecture** 패턴을 따르며, 각 계층이 명확한 책임을 가지고 있습니다.

## 1. 각 디렉터리의 역할 및 작성할 파일 내용

### 1.1 `app/core/` - 핵심 설정 계층
**역할**: 애플리케이션의 기본 설정을 관리합니다.

**포함 파일**:
- `app/core/config.py` — 환경 설정
- `app/core/db/databases.py` — DB 연결 설정
- `app/core/db/models.py` — 공통 모델 Mixin

**작성 방법**:
```python
# app/core/config.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DB_USER: str = "root"
    DB_PASSWORD: str = "password1234"
    DB_HOST: str = "localhost"
    DB_PORT: str = "3306"
    DB_NAME: str = "ai_health"
    
    model_config = {"env_file": ".env", "extra": "ignore"}

settings = Settings()
```

---

### 1.2 `app/models/` - ORM 모델 계층
**역할**: SQLAlchemy를 사용한 데이터베이스 테이블 정의

**작성 방법**:
```python
# app/models/user.py
from sqlalchemy.orm import Mapped, mapped_column
from app.core.db.databases import Base
from app.core.db.models import UUIDMixin, TimestampMixin

class User(Base, UUIDMixin, TimestampMixin):
    __tablename__ = "users"
    
    name: Mapped[str] = mapped_column(String(100))
    email: Mapped[str] = mapped_column(String(255), unique=True)
```

**특징**:
- `Base`를 상속하여 테이블 매핑
- Mixin 클래스를 상속하여 공통 필드 자동 추가
- SQLAlchemy 2.0+ 의 **Mapped** 타입 힌트로 타입 안전성 보장

---

### 1.3 `app/repositories/` - 데이터 접근 계층 (DAL)
**역할**: 데이터베이스 쿼리 로직을 캡슐화

**작성 방법**:
```python
# app/repositories/user_repository.py
from sqlalchemy.ext.asyncio import AsyncSession
from app.models.user import User

class UserRepository:
    def __init__(self, db: AsyncSession):
        self.db = db
    
    async def create(self, user_data: dict) -> User:
        user = User(**user_data)
        self.db.add(user)
        await self.db.commit()
        await self.db.refresh(user)
        return user
    
    async def get_by_id(self, user_id: uuid.UUID) -> User | None:
        return await self.db.get(User, user_id)
```

**장점**:
- DB 쿼리 로직을 중앙화
- 서비스 계층에서 DB 구현 세부사항 숨김
- 테스트 시 Mock Repository로 쉽게 대체 가능

---

### 1.4 `app/schemas/` - Pydantic 스키마 계층
**역할**: API 요청/응답 데이터 검증 및 직렬화

**작성 방법**:
```python
# app/schemas/user.py
from pydantic import BaseModel, ConfigDict
from typing import Optional
import uuid
from datetime import datetime

class UserCreate(BaseModel):
    name: str
    email: str

class UserResponse(BaseModel):
    uuid: uuid.UUID
    name: str
    email: str
    created_at: datetime
    
    model_config = ConfigDict(from_attributes=True)  # ORM → Pydantic 변환
```

**역할 분리**:
- `UserCreate`: POST/PATCH 요청 입력 검증
- `UserResponse`: GET 응답 직렬화
- `from_attributes=True`: SQLAlchemy ORM 모델 자동 변환

---

### 1.5 `app/services/` - 비즈니스 로직 계층
**역할**: 실제 비즈니스 로직 구현

**작성 방법**:
```python
# app/services/user_service.py
from app.repositories.user_repository import UserRepository
from app.schemas.user import UserCreate, UserResponse

class UserService:
    def __init__(self, user_repository: UserRepository):
        self.user_repository = user_repository
    
    async def create_user(self, user_create: UserCreate) -> UserResponse:
        # 비즈니스 로직: 검증, 변환 등
        user = await self.user_repository.create(user_create.dict())
        return UserResponse.from_orm(user)
```

**특징**:
- Repository에 의존하여 데이터 접근
- 비즈니스 규칙 구현 (검증, 변환)
- API 계층과 분리되어 재사용 가능

---

### 1.6 `app/apis/` - API 라우터 계층
**역할**: HTTP 엔드포인트 정의

**작성 방법**:
```python
# app/apis/user_router.py
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession
from app.core.db.databases import async_get_db
from app.services.user_service import UserService
from app.repositories.user_repository import UserRepository
from app.schemas.user import UserCreate, UserResponse

router = APIRouter(prefix="/api/v1/users", tags=["users"])

@router.post("", response_model=UserResponse)
async def create_user(
    user_create: UserCreate,
    db: AsyncSession = Depends(async_get_db)
):
    repository = UserRepository(db)
    service = UserService(repository)
    return await service.create_user(user_create)

# main.py에서
# from app.apis.user_router import router
# app.include_router(router)
```

**특징**:
- `Depends(async_get_db)`: 자동 세션 주입 및 정리
- 요청 데이터 자동 검증 (Pydantic)
- 응답 자동 직렬화
- Swagger UI 자동 생성

## 3. 데이터베이스 연결 설정

### 3.1 비동기 SQLAlchemy 구성
```python
# app/core/db/databases.py
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine, async_sessionmaker
from app.core.config import settings

DATABASE_URL = f"mysql+asyncmy://{settings.DB_USER}:{settings.DB_PASSWORD}@{settings.DB_HOST}:{settings.DB_PORT}/{settings.DB_NAME}"

async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)
AsyncSessionLocal = async_sessionmaker(bind=async_engine, autoflush=False, expire_on_commit=False)

async def async_get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as db:
        yield db
```

**주요 설정**:
- `DATABASE_PREFIX = "mysql+asyncmy://"` — MySQL 비동기 드라이버
- `create_async_engine()` — 비동기 엔진 생성
- `async_sessionmaker()` — 세션 팩토리
- `async_get_db()` — FastAPI 의존성 주입용 함수

### 3.2 FastAPI에서 사용
```python
@app.get("/users")
async def get_users(db: AsyncSession = Depends(async_get_db)):
    result = await db.execute(select(User))
    return result.scalars().all()
```

**특징**:
- **AsyncSession**: 논블로킹 데이터베이스 연결
- **Depends()**: 의존성 주입으로 세션 자동 관리
- **yield**: 요청 처리 후 세션 자동 종료


## 4. SQLAlchemy ORM과 Alembic 마이그레이션

### 4.1 ORM 모델 작성
```python
# app/models/user.py
from app.core.db.databases import Base
from app.core.db.models import UUIDMixin, TimestampMixin

class User(Base, UUIDMixin, TimestampMixin):
    __tablename__ = "users"
    
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    email: Mapped[str] = mapped_column(String(255), unique=True, nullable=False)
    age: Mapped[int | None] = mapped_column(Integer, nullable=True)
```

**포인트**:
- `Base` 상속으로 테이블 등록
- Mixin 상속으로 공통 필드 자동 추가
- `Mapped` 타입 힌트로 IDE 자동완성 지원

### 4.2 Alembic 마이그레이션 수행
```bash
# 1. 새 마이그레이션 생성 (자동 감지)
alembic revision --autogenerate -m "Add user model"

# 2. 생성된 마이그레이션 파일 확인 (alembic/versions/xxx.py)
# 필요시 수정

# 3. 데이터베이스에 스키마 적용
alembic upgrade head

# 4. 특정 마이그레이션으로 롤백
alembic downgrade -1

# 5. 마이그레이션 히스토리 확인
alembic history
```

**마이그레이션 파일 예시**:
```python
# alembic/versions/001_add_user_table.py
def upgrade() -> None:
    op.create_table(
        'users',
        sa.Column('uuid', mysql.CHAR(36), nullable=False),
        sa.Column('name', sa.String(100), nullable=False),
        sa.Column('email', sa.String(255), nullable=False, unique=True),
        sa.Column('created_at', sa.DateTime(), nullable=False),
        sa.Column('updated_at', sa.DateTime(), nullable=True),
        sa.PrimaryKeyConstraint('uuid')
    )

def downgrade() -> None:
    op.drop_table('users')
```

## 5. API 구현 흐름

### 5.1 요청 처리 프로세스
```
1. HTTP 요청 도착
   ↓
2. Pydantic 검증 (schemas/)
   ↓
3. 의존성 주입 (async_get_db)
   ↓
4. 라우터 핸들러 실행 (apis/)
   ↓
5. 서비스 계층 호출 (services/)
   ↓
6. 레포지토리 계층 호출 (repositories/)
   ↓
7. SQLAlchemy ORM 쿼리 (models/)
   ↓
8. 데이터베이스 접근 (databases.py)
   ↓
9. 응답 직렬화 (schemas/)
   ↓
10. HTTP 응답 전송
```

### 5.2 예제: 사용자 생성 API
```python

# 요청 본문: {"name": "John", "email": "john@example.com"}

@router.post("", response_model=UserResponse)
```
